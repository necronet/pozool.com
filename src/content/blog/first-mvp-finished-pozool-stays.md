In the previous post about the challenges of building a property management system in today’s ecosystem, we explored OTA barriers and other constraints. Now it is time to send this product into alpha: Pozool Stays is officially in its first public opening stage.

We have basically moved from promise and slides to a stable, functional version that already has initial active users helping refine the current workflows. There is still a long road ahead, and a lot to hear and learn. This first release brings together the essentials to run operations with less chaos:

- property and listing management
- short-term and long-term rental modules
- financial and operational controls

On a day-to-day operational level, it also includes: reservations, guests, payments, calendars, cleanings, maintenance, and expense tracking.

Pozool Stays already supports the common workflows of a real estate and hospitality operation without depending on scattered controls.

![Pozool Stays reservation management view](/blog-reservation-management-alpha.png)

## Features available today

| Area | Current features |
| --- | --- |
| Properties | Property creation and editing, step-by-step wizard, address, location, gallery, and images |
| Short-term rentals | Listings, global calendar, calendar connections, reservations, guests, payments, and photos |
| Operations | Cleanings, maintenance, operational expenses, payouts, and status tracking |
| Tasks | General tasks, tasks tied to properties or reservations, subtasks, and basic follow-up |
| Inventory and vendors | Inventories per property or unit, documents, inventory movements, and vendor directory |
| Administration | User profile, company data, team, security, global search, and viewer role |
| Activatable modules | Long-term rentals, finance, utilities, automated trackers, and operational staff |

The MVP goal was simple: solve the heaviest operational problems first, and leave behind a modular foundation that can keep growing without bloating the product from day one.

We are still in alpha, validating with real usage, tightening details, and learning from every workflow. That was the point from the start: build something useful, grounded, and ready to evolve with the people managing properties every day.

What matters about this milestone is not only being able to say “there is an MVP.” What matters is that this MVP already concentrates real processes in one place and leaves the next stage ready: more financial visibility, more automation, and better portfolio-wide control without losing the operational focus that made it useful from the start.

## What comes next

What comes next is refining the current features, listening more closely to alpha users, and continuing to improve the workflows that carry the most weight in day-to-day operations. At this stage, we care less about inflating the feature list and more about making what already exists genuinely useful for the people managing properties every day.

The alpha will keep expanding progressively at [Pozool Stays](https://stays.pozool.com), with more financial visibility, more automation, and a more integrated operation over time.
